73: 4. Mathematical and Lean Statement Problems
74: 11. The README falsely claims one zero produces all four completed-zeta evaluations
75: Severity: BLOCKER
76: Evidence: README.md line 6 says Λ(s) = 0 implies vanishing at all four symmetry evaluations. The Lean theorem completedRiemannZeta_fourfold_zero_orbit takes two hypotheses: a zero at σ + it and a zero at σ - it.
77: Assessment. The implication in the README is strictly stronger than the theorem. The theorem proves two functional-equation reflections after assuming both members of the conjugate pair. It does not derive the conjugate zero from the first zero.
78: Repair. Either prove completed-zeta conjugation symmetry and derive the four points from one zero, or rename the theorem to completedRiemannZeta_two_reflection_pairs and state both assumptions everywhere.
79: 12. Full Fourfold Zero Orbit is an inflated theorem name
80: Severity: MAJOR
81: Evidence: CompletedZetaSymmetry.lean lines 47-68 calls the result Full Fourfold Zero Orbit while assuming two of the four zero statements and returning them unchanged as the first and fourth conjuncts.
82: Assessment. Half of the conclusion is copied directly from the assumptions. The only derived content is one reflection from each assumed zero.
83: Repair. Use a literal name such as completedRiemannZeta_two_zero_reflections, or add a genuine conjugation theorem and derive the full orbit from one hypothesis.
84: 13. The paper describes parameter negation as if it were a derivation
85: Severity: MODERATE
86: Evidence: Theorem 6 lists σ - it as arising via parameter negation, but the Lean theorem receives that zero as h_zero_neg.
87: Assessment. Parameter negation changes an argument. It does not prove that a function remains zero at the new argument.
88: Repair. State that σ - it is a second assumption, not a consequence. Use conjugation symmetry if a consequence is intended.
89: 14. Hardy norm parameter symmetry is conditional, not proved
90: Severity: BLOCKER
91: Evidence: hardyZ_neg_norm takes h_symm as an explicit hypothesis that already states the needed zeta norm equality. The proof only rewrites both Hardy norms and applies h_symm.
92: Assessment. This is a transport lemma, not an independent symmetry theorem. The README and theorem mapping present the result without its hypothesis.
93: Repair. Rename it hardyZ_neg_norm_of_riemannZeta_norm_eq and print the hypothesis in the paper. Better, import the Mathlib conjugation theorem and prove the critical-line zeta norm equality first.
94: 15. The theorem dependency row for hardyZ_neg_norm is false
95: Severity: MAJOR
96: Evidence: The paper says the theorem is based on riemannZeta_conj and norm_star. The actual proof cites neither; it uses hardyZ_norm_eq_riemannZeta_norm and the supplied h_symm assumption.
97: Assessment. A formal mapping table that misstates proof dependencies is not a reliable audit table.
98: Repair. Generate dependency information from Lean output or manually correct the row to show the actual helper theorem and hypothesis.
99: 16. The title still calls the construction Hardy Z while the paper admits it is not proved real-valued
100: Severity: MAJOR
101: Evidence: The title and Section 4 use Hardy Z-Function. The abstract says the normalization is complex-valued and does not establish real-valuedness.
102: Assessment. The classical Hardy Z function is real-valued on real inputs. A complex phase multiple with only norm and zero equivalence proved is not yet the classical object promised by the title.
103: Repair. Rename the object and paper to complex critical-line phase normalization, or prove real-valuedness with a correctly normalized continuous theta function.
104: 17. The Riemann-Siegel theta definition is not proved to be the classical global theta
105: Severity: MAJOR
106: Evidence: riemannSiegelTheta uses the imaginary part of Mathlib principal Complex.log applied to Gamma. No continuity, branch normalization, parity, or agreement with the standard continuous theta is proved.
107: Assessment. The principal argument can jump by multiples of 2π. Naming it the classical Riemann-Siegel theta without branch analysis is unjustified.
108: Repair. Rename it principalGammaPhase until branch agreement is proved. For the classical function, construct or import a continuous argument with a stated normalization and prove equivalence on the intended domain.
109: 18. The introduction contradicts the abstract about the Hardy object
110: Severity: MODERATE
111: Evidence: The abstract calls H complex-valued and disclaims real-valuedness. The introduction says the library covers the classical Hardy Z-function.
112: Assessment. The same manuscript cannot both disclaim and assert the defining property of the classical object.
113: Repair. Use complex Hardy-type normalization consistently in the title, introduction, section heading, README, code comments, and citation title.
114: 19. The classical nonvanishing hypotheses are unused
115: Severity: MAJOR
116: Evidence: Nonvanishing.lean names the hypotheses _hne : s ≠ 1 and _ht : t ≠ 0, signaling that they are intentionally unused. The proofs ignore both and directly apply Mathlib totalized nonvanishing.
117: Assessment. The statements are logically valid, but the proofs do not formalize the claimed exclusion of the pole. They merely specialize a totalized theorem that also holds at the junk value.
118: Repair. Prove s ≠ 1 from t ≠ 0 and use a theorem or definition whose classical interpretation requires that side condition. At minimum, state that the side condition is interpretive and not used by the totalized proof.
119: 20. The classical and totalized one-line theorems collapse to the same proof
120: Severity: MODERATE
121: Evidence: riemannZeta_ne_zero_on_one_line and riemannZeta_ne_zero_totalized have the same conclusion and both apply riemannZeta_ne_zero_of_one_le_re; only the first carries an ignored t ≠ 0 assumption.
122: Assessment. The source does not encode the conceptual distinction that the paper emphasizes.
123: Repair. Keep one totalized theorem. Add a separate theorem about a pole-free domain or an explicitly partial/classical wrapper if the distinction is meant to exist formally.
124: 21. The completed-zeta fourfold result ignores available zeta conjugation infrastructure
125: Severity: MODERATE
126: Evidence: Pinned Mathlib documents riemannZeta_conj for all complex inputs. The local project does not build a corresponding completed-zeta conjugation theorem and instead assumes both conjugate zeros.

237: 8. Suggested Corrected Core Wording
238: Replacement abstract
239: We present a small Lean 4 library, pinned to Lean v4.30.0-rc2 and a fixed Mathlib revision, containing finite positive-index Dirichlet-polynomial conjugation lemmas, elementary products-of-norms identities, and coordinate wrappers for existing Mathlib theorems about the completed Riemann zeta function. We also define a complex critical-line phase normalization and prove norm and zero equivalence with the Riemann zeta function. A two-reflection theorem packages the functional-equation images of two assumed conjugate zeros. The library does not prove zero-density estimates, a one-zero fourfold orbit, real-valuedness of the classical Hardy Z function, or new zero-free regions. Verification claims refer only to the exact release commit and its public continuous-integration artifact.
240: Replacement fourfold wording
241: If completed zeta vanishes at both σ + it and σ - it, then the functional equation supplies zeros at (1 - σ) - it and (1 - σ) + it. This theorem packages two reflection pairs; it does not derive conjugate symmetry from one zero.
242: Replacement Hardy wording
243: Define H(t) as a complex phase multiple of ζ(1/2 + it). The formalization proves |H(t)| = |ζ(1/2 + it)| and H(t) = 0 iff ζ(1/2 + it) = 0. The present library does not prove that H is real-valued or that the chosen principal-branch phase equals the globally normalized classical Riemann-Siegel theta function.
244: Replacement verification wording
245: At release commit <SHA>, GitHub Actions run <RUN-ID> completed lake build and audited the listed declarations for sorryAx dependencies. The audit log is attached to that run. Claims about warnings or all declarations are made only when separately enforced by CI.
