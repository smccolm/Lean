## What is usable, and what it would still require

**AINTLIB has substantive new source bodies.** `GammaOneNaiveRelRep.lean` constructs affine relative representability of the naive Γ₁ problem when the level is a unit, using the finite étale level locus. `YOneAtlasClassify.lean` proves the Tate marked-point classifying clause. `WeilPairing/Basic.lean` now constructs its scheme-valued pairing through the Katz–Mazur backend; `KMDataset.lean` contains an explicit normalized-dataset construction. These should not be described as merely the old admitted interfaces. Their complete imported proof closures have **not** been kernel/axiom audited here.

The selected `NIsogeny.lean` still has actual admitted bodies in `quotient_smoothOfRelativeDimension`, `quotient_isProper`, `quotient_locallyWeierstrass`, `quotientHom_finite`, `quotientHom_flat`, `quotientHom_finrank` and `exists_gammaZeroSpace`, among others. `GammaHMaster.lean` visibly retains upstream representability, torsor and model inputs. Thus these selected results do not supply a checked smooth proper integral Γ₁ model, identify it with Dubon's original integral-ratio field, or give the required Picard specialization and Frobenius correspondence. Adopting the moduli route would first require those precise bridges and an audit of its dependency closure.

`HeckeT_p_Gamma1.lean` gives explicit Γ₁ double-coset/diamond formulas. The local project already has the original Hecke/diamond field, cohomology, period and arithmetic comparisons, including the native transfer's diamond invariance. This source is retained as a formula cross-check, not counted as a new discharge. Newer module syntax and local option overrides in selected AINTLIB files also require a native port; raw imports would not satisfy the fixed-pin contract. AINTLIB records Apache-2.0 licensing.

**ATLAS contains a concrete elliptic inertia proof.** `MathlibExt/AlgebraicGeometry/EllipticCurve/NeronOggShafarevich.lean` proves `good_reduction_torsion_unramified` for a Weierstrass elliptic curve over a discrete valuation field, with `HasGoodReduction`, a compatible valuation on a separable closure, and torsion order invertible in the residue field. Its valuation-filtration proof is a candidate for an actual elliptic input. It neither constructs the needed good reduction nor applies to the arbitrary-genus Γ₁ Picard group. `GaloisRepresentation.lean` constructs the natural elliptic torsion action; its header explicitly leaves the cyclotomic determinant identity in a wanted declaration. The corresponding native arithmetic Picard/Tate action is already available locally.

ATLAS's selected textbook `ModularCurves.lean` still has admitted topology, stabilizer and manifold declarations. Its arithmetic Picard exact-sequence file accepts a `CurveWithConstants` interface; the selected algebraic-geometry divisor file proves Dedekind-domain class-group statements. These do not provide the missing original modular-curve comparison. The root license contains the Apache-2.0 text preceded by an ML-development-use notice; that exact file is archived. No ATLAS source is copied into production.

## Route decision and verification boundary

Continue the shorter native route already supported by proved local results: integral Laurent fraction scaling → the original Γ₁ coefficient valuation → its actual Laurent residue image → regular prolongation and finite separating j-coordinate → arithmetic and Hecke reduction compatibility. This directly serves the original geometric Frobenius/inertia obligations. Native coordinate exchange also supplies finiteness of residue Hecke maps once their literal construction is checked. No separate scheme, Néron-model or general Jacobian framework is added for this milestone.

This route still must prove degree equality, genus preservation, compatible place/Picard specialization, torsion injectivity, and the two geometric Frobenius components. The new source review closes none of DUB-17–20 and does not justify removing those assumptions. Any later adoption of a candidate requires an exact original-object bridge, a fixed-pin build and complete axiom/dependency checks.
